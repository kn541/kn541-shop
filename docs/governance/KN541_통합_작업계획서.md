## 3. 승인 절차

CONST-060에 따라, 각 작업은 다음 절차를 따릅니다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1. 영향 분석 | 변경 대상 파일의 참조 관계, 의존 패키지, 영향받는 기능을 사전 조사 | 영향 범위 목록 |
| 2. 승인 요청 | 영향 범위 + 수정 계획을 operator에게 보고. 승인 없이 실행 금지. | 승인 기록 |
| 3. 실행 | 한 건씩 수정. 여러 건을 묶어서 하지 않는다. | 커밋 |
| 4. 검증 | 빌드, 타입체크, 프리뷰/스테이징 배포 후 해당 기능 수동 확인. | 검증 결과 |
| 5. 프로덕션 | HIGH는 프리뷰 24시간 운영 후. MEDIUM은 프리뷰 확인 후. | 배포 기록 |
| 6. 롤백 | 문제 발생 시 즉시 이전 버전으로 롤백. | 롤백 기록 |

## 4. 거버넌스 참조

```sql
SELECT * FROM gov_work_plan ORDER BY phase, work_code;
UPDATE gov_work_plan SET status='IN_PROGRESS' WHERE work_code='WORK-XXX';
UPDATE gov_work_plan SET status='DONE', completed_at=now() WHERE work_code='WORK-XXX';
```
